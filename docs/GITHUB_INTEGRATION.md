## Method

1. **Inventory.** `gh` was not authenticated in the working session (invalid token) and the
   GitHub API was not reachable from the session: the list comes from the session's repository
   inventory (15 own, 12 forks, 1 private). It is frozen in `integrations/inventory.yaml`, with
   the pillar classification. With `gh auth login`, `scripts/inventory_github.py --from-gh
   alebgl77` rebuilds the list from `gh repo list`; a new repository shows up as "unclassified"
   until a human review.
2. **Full clone** of each own repository (all branches, full history), reading of the README, the
   license file and the dependency manifests (`package.json` and `package-lock.json`,
   `pyproject.toml`, `requirements*.txt`, `go.mod`, `Cargo.toml`).
3. **Pillar classification** (`rag`, `evaluation`, `multi_agents`, `llmops_observability`,
   `governance_security`, otherwise `none`): a human decision, justified in
   `integrations/inventory.yaml`.
4. **Repository license**: identification of the text of the `LICENSE` file and consistency check
   with the declarations (`package.json`, `pyproject.toml`, `CITATION.cff`).
5. **Dependency licenses**: `package-lock.json` when it exists, otherwise the PyPI JSON API, the
   npm registry, pkg.go.dev or crates.io. Each license is evaluated against the policy of
   `licenses/third_party.yaml` (SPDX `AND` / `OR` expressions included). GPL, AGPL, LGPL, SSPL and
   unknown licenses are flagged; a copyleft or unknown **runtime** dependency blocks the
   integration, a development dependency is only flagged. Paths excluded from the analysis
   (justified in `integrations/inventory.yaml`): the third-party image rebuild recipes of
   open-shadow-ai (`requirements/service-builds/`: Prometheus, node_exporter and gosu, under
   Apache-2.0) and the tierdecay test bench. The lock files `requirements/runtime.txt` and
   `requirements/agent.txt` of open-shadow-ai are analyzed as well: the deployed transitive
   dependencies are therefore checked too.
6. **Secrets**: gitleaks **8.30.1** (pinned image `zricethezav/gitleaks:v8.30.1`, network
   disabled, repository mounted read-only) on the **full git history**, default rules; any
   gitleaks configuration of the scanned repository and `gitleaks:allow` comments are ignored.
   The redacted report (`--redact`) is deleted after reading. The rule, file, short commit and
   line are used in memory to match entries in `integrations/secrets-triage.yaml`. Any untriaged
   finding blocks integration. Published inventory outputs contain the scan status and counts.
   In `--report` JSON, `false_positive_count` and `remaining_count` give the two totals.
7. **Decision** (computed by the script):
   - `integrated`: pillar covered, permissive license, no copyleft or unknown runtime
     dependency, clean scan after triage;
   - `to_relicense`: pillar covered but no license, or a license the holder must change;
   - `excluded`: fork, private repository, no pillar, remaining secret or copyleft dependency.
8. **Integration**: `git submodule add https://github.com/alebgl77/<repo>.git integrations/<repo>`,
   link pinned to **the analyzed commit**, then generation of the catalog card. Nothing is
   committed automatically.

## Repositories to relicense under MIT

**Mandatory: none.** The 7 repositories that cover a pillar are under MIT or Apache-2.0, two
permissive licenses compatible with an MIT repository that references them as submodules.

**Optional, for a 100% MIT factory**: `open-shadow-ai` and `openspanguard` (Apache-2.0).
Apache-2.0 provides an explicit patent license and a `NOTICE` mechanism that MIT lacks:
relicensing is only useful if MIT uniformity is a requirement. The git history shows no third-party
human contributor (only your own commits and Dependabot): you
can therefore decide alone. Exact steps, for each of the two repositories:

1. Check the authors: `git log --format='%an <%ae>' | sort -u`. If a third-party contributor
   appears, obtain their written consent or rewrite their contribution.
2. Replace `LICENSE` with the MIT text: `Copyright (c) 2026 Alexandre Beguel`.
3. Update the declarations: `"license": "MIT"` in `package.json` (and `frontend/package.json` for
   open-shadow-ai), `license = "MIT"` in `pyproject.toml` and `agent/pyproject.toml`,
   `license: MIT` in `CITATION.cff`, README badges, `SPDX-License-Identifier` headers
   (`git grep -n "Apache-2.0"` to find them).
4. Keep the license and `NOTICE` files of **third parties** (for example
   `requirements/service-builds/*/LICENSE` and `NOTICE` in open-shadow-ai): they cover the upstream
   code, not yours.
5. Add to the `CHANGELOG`: "Relicensed from Apache-2.0 to MIT as of vX.Y.Z; earlier versions remain
   available under Apache-2.0" (a relicensing is not retroactive).
6. Publish a release, then in this repository:
   `git -C integrations/<repo> fetch && git -C integrations/<repo> checkout <tag>`,
   `python scripts/inventory_github.py --only <repo> --write-cards` (reruns the scan) and
   `python scripts/check_licenses.py`.

**Outside the pillars, without a license**: `alebgl77` (profile README) and `alebgl77.github.io`
(profile website). Nothing is required for the factory. If you want to allow their reuse, add a
`LICENSE` file (GitHub: *Add file → Create new file → LICENSE → Choose a license template*); for
text and showcase pages, CC-BY-4.0 is a better fit than MIT.

**Notice hygiene (not a relicensing)**:

- generic holder in the MIT text: "contributors" (grafana-llmops-forge, ftp-deploy-mcp),
  "TierDecay contributors", "Briefoak contributors" (pilovo, former name?). Prefer
  `Copyright (c) 2026 Alexandre Beguel and contributors`;
- missing `license` field: `pyproject.toml`, `agent/pyproject.toml` and `frontend/package.json` of
  open-shadow-ai, `package.json` of generative-engine-monitor;
- unpinned `latest` versions in the `package.json` of pilovo (outside the pillars).

## Reproduce and update

```bash
# Fetch the submodules after a clone
git submodule update --init

# Full inventory: clone, licenses, dependencies, gitleaks, cards, table of this document
python scripts/inventory_github.py --report /tmp/inventory.json \
  --markdown docs/GITHUB_INTEGRATION.md --write-cards --add-submodules

# With an authenticated gh, list built from GitHub
gh auth login && python scripts/inventory_github.py --from-gh alebgl77 --report /tmp/inventory.json

# Self-test of the decision rules (no network), then license check of the whole repository
python scripts/inventory_github.py --self-test
python scripts/check_licenses.py
```

Bump a submodule: `git -C integrations/<repo> fetch && git -C integrations/<repo> checkout
<commit>`, then rerun the inventory with `--only <repo>`: a new commit must be **rescanned**
before being committed (the card shows the analyzed commit in `commit`). Remove a repository:
`git submodule deinit -f integrations/<repo>`, `git rm -f integrations/<repo>`,
`rm -rf .git/modules/integrations/<repo>`, then delete its card. Fix a classification: edit
`integrations/inventory.yaml` and rerun the script (the cards are generated: do not edit them by
hand).

## Where to start

| If you are… | Start here | Look for |
|---|---|---|
| Exploring the Factory or facilitating a workshop | Open the [demo](https://alebgl77.github.io/ai-factory/?lang=en), use **Visit** (`M`), then run the [UC-04 workshop](https://alebgl77.github.io/ai-factory/exercise/?lang=en) or the [Flow Lab](https://alebgl77.github.io/ai-factory/docs/flow-lab.html?lang=en). | A fictional release decision, GPU outage, route refusal and an exportable decision record from the workshop. |
| Leading a project, managing a team or reviewing technical work | Open **Planning → Portfolio and tasks**. | Approving a decision or integrating an agent | Open **Decision Companion**. Try the fictional CRM-to-ERP scenario, then run the SDK example locally. [Workbench](WORKBENCH.md) · [SDK, CRM, MCP and ERP contract](ADAPTIVE_WORKBENCH.md) | The case revision, evidence, separate approval and the draft receipt or reconciliation status. |
| Operating or securing a private pilot | Follow the [Compose deployment guide](DEPLOYMENT.en.md) or [Kubernetes installation](KUBERNETES.md) and [operations](KUBERNETES_OPERATIONS.md), then use the [hardening guide](SECURITY.md#14-production-hardening-guide). | Signed artifacts, effective edge and BU controls, a repeatable restore and verified delivery to telemetry and security destinations. |
| Measuring usage, cost or adoption | Open **Factory → AI Usage Observatory**, **Factory → Agent Ops → Work history**, or **FinOps** depending on the question. [Observatory](SHADOW_AI.md) · [Work history](WORKBENCH.md#work-history-and-token-evidence) · [FinOps](FINOPS.md) | Monthly adoption counts, evidence of a specific run, or attributed platform costs. ## How the data moves

The browser calls the dashboard and `/api/v1/` on the same origin. Caddy and the identity proxy form the trusted edge for protected deployments. The API uses the verified identity and BU policy when producing views and authorizing writes. Browser clients receive projected data and status. Model keys, connector credentials and Grafana service tokens stay with their trusted hosts.

| Capability | Source → control → result | Boundary and reference |
|---|---|---|
| Snapshot, governance and LLMOps | `config/`, mutable API state and telemetry → `GET /api/v1/snapshot?lang=en` and register/pipeline views → operating picture. Scoped producers can publish deployment and drift receipts under `/api/v1/operating-evidence`. | In `auto` mode, missing data sources can use simulated data. In `never` mode, unavailable data is omitted. An evaluated release needs a current approval and independent evidence before a deployment is observed. Drift can recommend action. Reindexing, evaluation sets, routing and human review are the feedback mechanisms. [Architecture](ARCHITECTURE.md) · [Operating evidence (FR)](OPERATING_EVIDENCE.md) |
| Projects, BUs and sub-agents | Objectives → projects → tasks and dependencies → assigned human or catalog agent → evidence, technical review or Workbench. The optional runner uses the bound virtual key for `chat-sensitive`. | Child tasks stay in their parent's project and BU, with one level and at most four children over the parent's lifetime. Autonomy is BU policy. `provider_reported` usage from the runner and `agent_reported` usage from the assigned agent stay distinguishable. [Portfolio](PORTFOLIO.md) · [BU policy](BU_SECURITY.md) · [Gateway policy](GATEWAY_SECURITY.md) |
| CRM and ERP | Salesforce Opportunity/Account, HubSpot deal/company or Twenty opportunity/company → read-only SDK polling and exact customer reference → Workbench case → eligible human approval → draft connector and independent read-back. | Use per-account read credentials and stable instance aliases. The CLI uses a simulated ERP and the bundled Odoo probe is read-only. A real ERP needs an operator-supplied `DraftConnector`, a target-enforced idempotency key and independent read-back. [CRM configuration](ADAPTIVE_WORKBENCH.md#connect-salesforce-hubspot-or-twenty) · [ERP adapter](ADAPTIVE_WORKBENCH.md#connect-a-draft-erp-adapter) |
| MCP and decisions | Local MCP stdio process → configured workspace and work profile → case preparation and read tools → separate approval in the trusted host. Portfolio Workbench decisions reconcile to the submitted task revision. | The packaged MCP command runs as a workspace editor and uses the ERP sandbox. A Portfolio decision records approval of the submitted work. External effects use their connector's approval path. [MCP setup](ADAPTIVE_WORKBENCH.md#connect-an-mcp-client) · [Decision Companion](WORKBENCH.md) |
| Assistance and Flow Lab | A form or decision question can use rules in the demo or a BU-scoped local model via `/api/v1/assist`. Separately, Flow Lab evaluates a fictional graph in the browser and keeps simulation history locally. | The user reviews any proposed text before inserting it. The market brief prepares research from supplied material. Verified public or internal collection requires a separate integration. Flow Lab's token, latency and cost figures are estimates from configured scenarios. [Assistance and Flow Lab](ASSIST_AND_FLOW_LAB.md) |
| Usage, adoption and tokens | Open Shadow AI → operator bridge → organization rollup. Approved roster and instrumented usage → monthly aggregates → team map and adoption. LiteLLM and other run producers supply distinct cost and work-history evidence. | Discovery signals, active/eligible populations, provider token counts and agent reports answer different questions. Missing tokens are unknown and explicit zero remains zero. The Workbench history records run intervals and provenance. [Observatory](SHADOW_AI.md) · [Work history](WORKBENCH.md#work-history-and-token-evidence) · [FinOps](FINOPS.md) |
| Security, SIEM and CVEs | Workbench security events → optional hash-chained journal → HMAC-authenticated checkpoints and minimized JSONL export → SOC receiver. Trivy reports and CISA KEV → versioned package inventory correlation → triage. | Operators configure signing, forwarding and retention and verify the destination. Alloy log collection and Workbench journal export are separate paths. Coverage depends on the deployed inventory, report freshness and scanner coverage. [Cyber operations](CYBER_SECURITY.md) · [Kubernetes logging](KUBERNETES_OPERATIONS.md#send-pod-logs-to-loki) |
